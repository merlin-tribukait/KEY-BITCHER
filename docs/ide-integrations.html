IDE & terminal integrations

💬

Error message #42: "Your .env has opinions. Your .env is wrong."

The tool is just a CLI, so any editor/terminal that can run a command can use
it. The repo ships ready-made integrations that add it as a task/action.

VS Code

.vscode/tasks.json defines:

Task Command
key-bitcher: build cargo build --release
key-bitcher: clippy cargo clippy --release -- -D warnings
key-bitcher: test cargo test --release
key-bitcher: fmt cargo fmt
key-bitcher: auto (sync + wave + benchmark) runs the binary, no args
key-bitcher: sync-secrets runs sync-secrets
key-bitcher: benchmark runs benchmark
key-bitcher: wave-import runs wave-import

.vscode/extensions.json recommends the Rust extension. Run a task with
Ctrl+Shift+P → Run Task.

Visual Studio (.vs/tasks.vs.json)

An key-bitcher task runs the auto flow inside VS, letting you refresh keys
without leaving the IDE.

JetBrains (RustRover, IntelliJ)

.idea/runConfigurations/ ships run configurations:

  • key-bitcher-auto, key-bitcher-bench, key-bitcher-build, key-bitcher-clippy,
    key-bitcher-sync, key-bitcher-test, key-bitcher-wave-import

These appear in the run-configuration dropdown. The .idea/* folder is
gitignored except the run configurations, so each checkout keeps the configs
without committing editor churn.

Terminals

integrations/terminal/ provides wrappers:

Wrapper Shell
key-bitcher.cmd cmd.exe
key-bitcher.ps1 PowerShell
key-bitcher.sh Bash/Zsh

integrations/system/env-loader.ps1 sources .env into the current session;
integrations/system/install-path.ps1 adds the build output to PATH so
key-bitcher is always callable. key-bitcher rust-setup wires all of these up
automatically on a fresh machine.
