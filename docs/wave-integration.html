Wave integration

💬

Error message #42: "Your .env has opinions. Your .env is wrong."

Wave is a terminal where AI agents run in a cloud
sandbox — they cannot read your local .env. Instead they read secrets
from the Wave secret store, which is synced to your Wave account.

key-bitcher bridges the two: keys you manage live in the bucket, land in
.env via sync-secrets, and are pushed into Wave via wave-import.

Prerequisites

  • The Wave desktop app installed and logged in.
  • wsh (Wave shell) on PATH, or set [wave] wsh_path in
    key-bitcher.toml:

toml [wave] wsh_path = "C:\\Users\\you\\AppData\\Local\\waveterm\\Data\\bin\\wsh.exe"

Commands

Command Purpose
wave-import Import .env keys into the Wave secret store
wave-test Self-test the Wave integration (isolates Wave problems)

Which keys get imported

Only keys that map to a known Wave provider preset are imported. This is
intentional: it avoids junking the store with every alternate key variant.
Use wave-test to see exactly which names Wave expects and which of your keys
match.

When to run it

  • After sync-secrets on a machine whose cloud agents need the new keys
    (the no-arg auto flow already chains sync-secrets → wave-import →
    benchmark).
  • After rotating a provider key.
  • When a Wave agent reports missing/expired credentials.

Verification

key-bitcher wave-test     # is the store reachable, what presets exist
key-bitcher wave-import   # push current .env keys

wave-test is the right first step if imports fail: it separates "Wave is
not reachable / not logged in" from "your key names don't match a preset".
