Security

💬

Error message #42: "Your .env has opinions. Your .env is wrong."

This tool moves real API keys. This page is the threat model and the
operating rules that keep it safe.

Threat model

Threat Mitigation
Key leaked into the repo .env, secrets.json, key-bitcher-notifications.md, logs are gitignored; CI runs gitleaks and fails on any finding
Local user reads your .env Restrict permissions (see below); the tool documents but cannot enforce host OS ACLs
Bucket keys compromise Use a scoped keypair (bucket-only), never the B2 master key, in .env
Bad overwrite of canonical key set Bucket versioning enabled; s3-versioning verifies it
Expired/rotated key promoted by accident benchmark tries all alternates and promotes only a working key
Copy/paste error in a handout import-md structural validation + validate dry-run
Supply-chain (TLS, deps) rustls-ring (no OpenSSL), Dependabot for Cargo + Actions

Operating rules

1. Never commit secrets

The real .env, generated secrets.json, notification files, and log files
are gitignored. .env.example is a template with empty values only. CI's
gitleaks step is a second line of defense.

2. Use scoped bucket keys

Put a bucket-scoped application key in .env, not the Backblaze master
key. A master key in a .env that leaks gives away every bucket you own; a
scoped key limits the blast radius to one bucket.

3. Restrict file permissions

Use the built-in command instead of manual ACLs:

key-bitcher secure            # restricts .env and secrets.json to the current user
key-bitcher secure --paths C:\path\to\.env

On shared machines, this stops other local users from reading your keys.

4. Rotate when something leaks

A key that appears in a commit, a chat log, or a screenshot is burned —
regardless of "we deleted it". Revoke at the provider, remove it from the
bucket, and re-upload. See SECURITY.md.

5. Delete intermediate files

secrets.json is an intermediate artifact. import-md uploads in-memory and
never writes it; if you produced one another way, delete it after a
successful upload, and run key-bitcher secure to lock down any copies that do
exist.

What the tool stores

Location Contents Notes

Reporting a vulnerability

Do not open a public issue with key material. Email
merlin_felix_@hotmail.com or file an issue describing the code path without
any secrets. See SECURITY.md.
