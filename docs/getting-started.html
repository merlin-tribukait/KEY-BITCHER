Getting started

💬

Error message #42: "Your .env has opinions. Your .env is wrong."

Requirements

  • Rust toolchain 1.70+ (the tool is a native binary, no runtime needed after build)
  • A private S3-compatible bucket (Backblaze B2 is the default and supported
    first-class; the bucket uses versioning for recovery)
  • Windows, Linux, or macOS — the binary is portable

Install

# PowerShell
.\build.ps1 -Profile release -Test

or manually:

cargo build --release

The binary is target/release/key-bitcher. On Windows the executable is
key-bitcher.exe.

Shell wrappers

integrations/ ships wrappers that put the tool on your PATH and load your
.env in every new terminal:

File Purpose
integrations/system/env-loader.ps1 Load .env into the current shell
integrations/system/install-path.ps1 Add the build output dir to PATH
integrations/terminal/key-bitcher.cmd Windows cmd wrapper
integrations/terminal/key-bitcher.ps1 PowerShell wrapper
integrations/terminal/key-bitcher.sh Bash/Zsh wrapper

key-bitcher rust-setup automates the whole bootstrap on a fresh machine.

First run

  1. Copy .env.example to .env and fill in:
    - AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION — bucket access
    - any provider keys you want managed
  2. Make sure key-bitcher.toml points at your team's bucket.
  3. Run key-bitcher sync-secrets to pull the canonical key set into .env.
  4. Run key-bitcher benchmark to confirm every provider accepts the keys.
  5. Run plain key-bitcher for the full daily flow.

Common workflows

New machine: rust-setup → sync-secrets → benchmark

Daily refresh: key-bitcher (no args)

After rotating a key: update the bucket (upload), then sync-secrets
and wave-import.

Before trusting a handout: import-md --file handout.md, review the
parsed keys, then upload when it looks right.
